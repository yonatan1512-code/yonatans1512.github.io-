# SmartSaver AI

דף נחיתה + סימולטור + לוח בקרה.

## הדרך הרגילה — כתובת מקומית שתמיד עובדת

**לחיצה כפולה על `SmartSaver AI` שעל שולחן העבודה** (האייקון הכחול).

או להקליד ב**שורת הכתובת** של הדפדפן:

```
http://localhost:8000
```

> חשוב: זו שורת הכתובת שלמעלה — **לא** תיבת החיפוש של גוגל.
> אם כותבים את זה בחיפוש, גוגל מחפש את זה כמילים ולא פותח את האתר.

השרת מוגדר לעלות **אוטומטית בכל כניסה לווינדוס**, ברקע בלי חלון.
אין מה להפעיל ידנית.

| רוצה | הרץ |
|---|---|
| לבטל את ההפעלה האוטומטית | `autostart-off.bat` |
| להחזיר אותה | `autostart-on.bat` |
| להפעיל פעם אחת בלי אוטומציה | `server-start.bat` |
| לעצור עכשיו | `server-stop.bat` |

## גיבוי: בלי שרת בכלל

אם משהו משתבש עם השרת — **לחיצה כפולה על `smartsaver-ai-complete.html`**
עובדת תמיד. נבדק: כולל שמירת היעד וההתקדמות, שנשמרים גם אחרי סגירת הדפדפן.

## הרצה עם חלון גלוי (localhost)

**לחיצה כפולה על `server-start.bat`.**

השרת עולה ברקע *בלי חלון* — כלומר הוא ממשיך לרוץ גם אחרי שהחלון הקטן נסגר.
הדפדפן ייפתח לבד, והכתובת היא:

```
http://localhost:8000
```

> את הכתובת מקלידים ב**שורת הכתובת** של הדפדפן (למעלה) — לא בתיבת החיפוש של
> גוגל. אם כותבים אותה בחיפוש, גוגל יחפש אותה כמילים ולא יפתח את האתר.

לעצירה: **`server-stop.bat`**.
הפלט נרשם ל-`server.log` בתיקייה.

### עם חלון פתוח (למפתחים)

`start.bat` מריץ את אותו שרת אבל בחלון גלוי, עם לוג חי של כל בקשה.
החלון חייב להישאר פתוח. או מהטרמינל:

```
python server.py
```

| פקודה | מה זה עושה |
|---|---|
| `python server.py 5500` | מריץ על פורט אחר |
| `python server.py --no-open` | לא פותח דפדפן |

לעצירה: `Ctrl+C`.

### אם השרת לא עולה

| מה קורה | למה | פתרון |
|---|---|---|
| החלון נפתח ונסגר מיד | פייתון לא מותקן / לא ב-PATH | `start.bat` מדפיס הודעה ומחכה — קרא אותה. אפשר גם פשוט לפתוח את `smartsaver-ai-complete.html` |
| `localhost:8000` לא נטען | השרת לא רץ | חלון הקונסולה חייב להישאר פתוח כל עוד אתה משתמש באתר |
| `Could not start the server on port 8000` | פורט תפוס | השרת עובר אוטומטית לפורט הבא ומדפיס את הכתובת החדשה |
| הדפדפן מציג עמוד ישן | קאש | השרת שולח `no-store`, אבל ב-`file://` נסה `Ctrl+F5` |

השרת מדפיס כל בקשה בזמן אמת — אם אתה רואה `✓ "GET ... 200"`, הכול תקין.

## איך מגיעים ללוח הבקרה

לוח הבקרה נפתח רק אחרי שיש יעד שמור. בדף הבית:

1. עוברים לקטע **הצטרפות** ומזינים אימייל.
2. כפתור **"לוח הבקרה"** (בזהב) מופיע בסרגל העליון, בתפריט המובייל ובתפריט החשבון.

מי שנכנס ל-`dashboard.html` בלי יעד שמור מקבל מסך נעילה עם קישור ליצירת היעד הראשון.

## איך זה מסונכרן

שני הדפים קוראים וכותבים לאותה רשומה ב-`localStorage`:

```
smartsaver_current_user          → האימייל המחובר
smartsaver_user:<email>          → היעד, ההכנסות, ההוצאות, הקיצוץ, היסטוריית ההפקדות
smartsaver_lang                  → שפה
smartsaver_theme                 → מצב בהיר/כהה
smartsaver_accent_rgb            → צבע הרקע שנבחר
smartsaver_a11y_*                → הגדרות הנגישות
```

כברירת מחדל הכל נשאר על המכשיר — שום דבר לא נשלח לשום מקום.
עם Supabase מוגדר (ראו למטה) הרשומה הזו מסונכרנת גם בין מכשירים.

## הוספה למסך הבית (PWA)

האתר מותקן כמו אפליקציה — אייקון על מסך הטלפון, בלי סרגל דפדפן, ועובד גם בלי אינטרנט.

| מכשיר | איך |
|---|---|
| **אנדרואיד / Chrome** | תפריט ⋮ ← **התקן אפליקציה** / **הוסף למסך הבית** |
| **אייפון / Safari** | כפתור השיתוף ← **הוספה למסך הבית** |
| **מחשב / Chrome** | אייקון ההתקנה בשורת הכתובת |

| קובץ | תפקיד |
|---|---|
| `manifest.webmanifest` | שם, צבעים, אייקונים, קיצור דרך ללוח הבקרה |
| `sw.js` | Service Worker — שומר את האתר בקאש לעבודה אופליין |
| `icon-192.png` · `icon-512.png` · `icon-maskable-512.png` | האייקונים |
| `make-icons.py` | מייצר את האייקונים מחדש (`python make-icons.py`) |

> **חייב שרת.** Service Worker לא נרשם מ-`file://` — צריך `localhost` או אתר אמיתי.
> הקוד בודק את זה לבד ומדלג בשקט, אז לחיצה כפולה על הקובץ עדיין עובדת, פשוט בלי התקנה.
>
> **`smartsaver-ai-complete.html` לא ניתן להתקנה** — קובץ בודד בלי manifest ואייקונים
> לצידו. תגיות ה-PWA מוסרות ממנו אוטומטית בבנייה כדי שלא ייווצרו 404.

**אחרי עריכה של קבצי האתר:** העלה את `CACHE` ב-`sw.js` (למשל `smartsaver-v4`),
אחרת הדפדפן ימשיך להגיש את הגרסה הישנה מהקאש.

## גיבוי ושחזור

מכיוון שהכל יושב ב-`localStorage`, **ניקוי היסטוריית הגלישה מוחק את היעד וההפקדות**.
בתחתית לוח הבקרה יש כרטיס **"גיבוי ושחזור"**:

| כפתור | מה קורה |
|---|---|
| **הורדת גיבוי** | יורד `smartsaver-backup-YYYY-MM-DD.json` עם כל המפתחות |
| **שחזור מקובץ** | בוחרים קובץ, מאשרים, והדף נטען מחדש עם הנתונים |

זו גם הדרך **להעביר את הכל לטלפון או למחשב אחר**: מורידים כאן, משחזרים שם.

השחזור מוחק קודם את כל מפתחות `smartsaver_*` הקיימים כדי שלא יישארו שאריות,
ולא נוגע בשום מפתח אחר בדפדפן. תור השליחה לגיליון (`smartsaver_sheet_queue`)
לא נכלל בגיבוי — הוא מצב זמני, לא נתוני משתמש.

> **חשוב:** כפתור השחזור קיים גם **במסך הנעילה** — כי מכשיר חדש הוא בדיוק
> המצב שבו צריך אותו, ושם אין עדיין נתונים.

## חשבון אמיתי וסנכרון בין מכשירים — Supabase (אופציונלי)

עד כאן הכול חי ב-`localStorage` של דפדפן אחד. עם Supabase יש חשבון אמיתי:
נכנסים מהטלפון ומהמחשב עם אותו אימייל וסיסמה, ורואים את אותו יעד ואת אותן
הפקדות.

**המדריך המלא:** [`supabase/README.md`](supabase/README.md) — 7 שלבים, בערך 10 דקות.

בקצרה: פותחים פרויקט ב-supabase.com ← SQL Editor ← מריצים את
[`supabase/schema.sql`](supabase/schema.sql) ← מעתיקים `Project URL` ו-`anon public`
מ-Project Settings → API ← מדביקים ב-`window.SS_SUPABASE` שבראש **שני** קבצי ה-HTML.

| מצב | מה קורה |
|---|---|
| `url: ''` (ברירת מחדל) | האתר מתנהג בדיוק כמו קודם — התחברות מקומית, אפס בקשות רשת |
| `url` מלא | התחברות דרך Supabase Auth, והרשומה מסונכרנת בין כל המכשירים |

`localStorage` נשאר המקור לאמת של המסך גם כשהענן דלוק, כך שהקלדה אף פעם לא
מחכה לרשת והאתר עובד במלואו גם בלי אינטרנט. אם Supabase לא זמין בזמן
ההתחברות, הכניסה נופלת חזרה לגיבוב המקומי והמשתמש מקבל על כך הודעה.

הפקדות מאוחדות לפי חותמת זמן בין מכשירים, ולא לפי "מי שמר אחרון" — כדי שהפקדה
שנרשמה בטלפון לא תימחק על ידי מחשב שהיה פתוח על נתון ישן.

> **שינוי אבטחה:** עמודת הסיסמה בגיליון גוגל תמיד ריקה מעכשיו. קודם נשלחה לשם
> הסיסמה בטקסט גלוי — מרגע שיש Supabase Auth אין לזה הצדקה.

## Database ב-Google Sheets (אופציונלי)

אפשר לחבר את האתר לגיליון גוגל, וכל פעולה (הרשמה, עדכון יעד, הפקדה,
התנתקות) תיכתב שם כשורה חדשה.

**המדריך המלא:** [`google-sheets/README.md`](google-sheets/README.md) — 7 שלבים, בערך 10 דקות.

בקצרה: יוצרים גיליון ← Extensions ← Apps Script ← מדביקים את
[`google-sheets/Code.gs`](google-sheets/Code.gs) ← Deploy as Web App ← מעתיקים
את כתובת ה-`/exec` ומדביקים אותה ב-`window.SS_SHEETS.url` שבראש כל קובץ HTML.

| מצב | מה קורה |
|---|---|
| `url: ''` (ברירת מחדל) | האתר מתנהג בדיוק כמו קודם, שום בקשת רשת לא יוצאת |
| `url` מלא | כל פעולה נרשמת בגיליון, והטקסט באתר מתעדכן אוטומטית ומפסיק להבטיח שהנתונים נשארים רק על המכשיר |

היעד וההתקדמות ממשיכים להישמר ב-`localStorage` בכל מקרה. הגיליון הוא יומן
פעולות בלבד — מחיקת ה-`url` מחזירה את האתר למצב המקורי בלי לשבור כלום.
אם אין אינטרנט, שורות שלא נשלחו נשמרות בדפדפן (עד 50) ונשלחות אוטומטית אחר כך.

## שפה ומטבע

האתר **בעברית בלבד**, וכל הסכומים — כולל המנויים — **בשקלים**.

[`languages-backup/`](languages-backup/) עם הוראות החזרה מלאות.
